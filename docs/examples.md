# Examples

以下示例均为匿名化场景，只展示模式选择与停止边界。

## Example 1：新 Web 项目

输入：

```text
使用 project-governance-bootstrap 初始化这个网站项目。
先立项，不开发功能。
```

行为：进入 `NEW`，确认项目身份、保护现有文件、建立 Git 与核心文档基线、添加适合实际技术栈的最小验证。提交后停止，不开始页面开发，不创建 remote，不 deploy。

## Example 2：已有 App

输入：

```text
对当前 App 做只读体检。
```

行为：进入 `AUDIT`，检查仓库、实现目录、文档、敏感信息、唯一资产和验证能力，输出 P0/P1/P2 与 Level A/B/C。报告后停止，不自动修改工程文件。

## Example 3：创作 / Skill 工作区

场景：工作区根目录不是 Git repository，实际代码位于一个子目录，原始图片和音频散落在 Git 之外。

行为：体检先确认真正的 repository 边界，列出 Git 外唯一素材及备份风险，并标记多项目工作区串线风险。不能把根目录误当成单一项目，也不能因为素材未被 Git 追踪就删除或移动。若用户随后要求治理，先解决资产安全，再处理 Git 与文档。

## Example 4：平台型项目

场景：构建、单元测试与本地预览均通过，但尚未在托管平台或真实设备验证。

行为：报告 `Local Verified`，同时明确 `Platform Verified` 尚未完成。没有部署结果、平台状态或真机证据时，不能声称“已上线”“审核通过”或“平台 API 可用”。
